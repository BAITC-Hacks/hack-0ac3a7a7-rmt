# Freedom AML — граф денег

Объяснимый анализ четырёхколенного графа внутрибанковских переводов. Скрипт назначает каждому клиенту роль, выделяет сообщества и ранжирует узлы для AML-проверки.

## Быстрый запуск

```powershell
python -m pip install -r requirements.txt
python starter.py --data ./data --out ./out
python -m http.server 8000
```

После этого открыть: <http://localhost:8000/ui/>

Для чистого окружения Windows:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe starter.py --data ./data --out ./out
.\.venv\Scripts\python.exe -m http.server 8000
```

## Результаты

- `out/nodes_roles.csv` — ровно 2 248 узлов, роль, уверенность, приоритет и числовое объяснение;
- `out/clusters.csv` — сообщества, внутренний оборот, лидеры и гипотеза назначения;
- `out/top_nodes.csv` — 30 первых кандидатов на AML-проверку;
- `out/graph_data.js` — связный риск-контур для интерфейса.

Запуск на предоставленном датасете занимает около трёх секунд.

## Как работает модель

Для каждой роли считается независимый скор, затем выбирается максимальный:

- `consolidator` — много плательщиков и входящих операций, мало каналов выхода;
- `distributor` — веерная рассылка большому числу получателей;
- `transit` — вход и выход совпадают по объёму и дням;
- `terminal` — наблюдаемое накопление без дальнейшего движения;
- `coordinator` — мост между seed-ветвями и кластерами;
- `peripheral` — нет выраженного структурного паттерна.

Используются направленные степени, суммы и количества операций, PageRank, приближённое betweenness, articulation points, циклы, встречные переводы, число seed-ветвей и совпадение входа/выхода по дням. Метрики нормализуются percentile rank, чтобы единичный крупный перевод не задавил остальные сигналы.

Кластеры строятся Louvain на ненаправленной проекции только для группировки. Вес связи — логарифм суммы с поправкой на количество транзакций. Роли и движение денег всегда считаются на исходном направленном графе.

## Ограничения, учтённые в расчёте

- Узлы четвёртого колена цензурированы: отсутствие исходящих не доказывает оседание денег. Для них снижается наблюдаемость, а объяснение содержит предупреждение.
- Входящие потоки могут быть неполными у любого узла, особенно у seed. Поэтому `out_kzt / in_kzt > 1` не считается самостоятельной аномалией.
- Транзакции имеют точность только до дня. Совпадение в один день — поддерживающий, но не доказательный признак транзита.
- Порог 5 000 KZT, операции вне банка и остатки до июля не наблюдаются.
- `depth` — глубина обнаружения, а не организационная иерархия.

## Воспроизводимость

Алгоритм детерминирован (`seed=42`) и не требует API-ключей или интернета для расчёта. Интернет нужен только браузеру для загрузки `vis-network` из CDN.
